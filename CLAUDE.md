# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm start` — Expo dev server (Metro)
- `npm run android` / `npm run ios` — `expo run:*` (native build, requires dev client). The app uses `expo-dev-client`, `expo-modules` requiring native code, and Firebase/RevenueCat/AdMob, so Expo Go will not work; always use a dev build.
- `npm run web` — web target (Metro static)
- EAS builds: `eas build --profile preview` (internal APK) or `--profile production` (auto-increment APK). EAS project id and runtime version live in [app.json](app.json).
- No test runner is configured. `react-test-renderer` is installed but there is no `test` script — do not invent one.
- TypeScript is `strict`. There is no separate typecheck script; run `npx tsc --noEmit` if needed.

## Architecture

### Navigation & boot sequence

Routing is **expo-router** with typed routes (`experiments.typedRoutes: true`). Two route groups:
- [app/(auth)/](app/(auth)/) — `welcome`, `login`, `register`
- [app/(main)/](app/(main)/) — `index` (home, contains internal tab switcher) and `saved`

The single source of truth for app boot is [app/_layout.tsx](app/_layout.tsx). It:
1. Wraps the tree in `LanguageProvider → ThemeProvider → RevenueCatProvider`.
2. Configures Google Sign-In, waits for the Zustand auth store to hydrate from AsyncStorage, then sets `isReady`.
3. Redirects based on token presence: no token → `(auth)/welcome`; logged in inside `(auth)` → `(main)`.
4. Detects logged-out → logged-in transitions and renders `<OnboardingScreen>` once before entering `(main)`.
5. Subscribes to notification taps (`expo-notifications`) and stashes the tapped event in `useNotificationEventStore` for the home screen to consume.
6. Calls `useGamificationSync()` and `useAdsInit()` for cross-cutting side effects.

**Tab UI lives inside [app/(main)/index.tsx](app/(main)/index.tsx)** — it is not implemented as expo-router tabs. The home screen renders its own `<TabBar>` and switches between `today / discover / universes / timeline / map / saved` views internally. Don't add a separate tab layout file; edit the in-screen switcher.

### Networking

[api.ts](api.ts) exports a single shared axios instance. All API calls must go through it.
- Base URL is the Railway dev server (`/api/v1`).
- Request interceptor waits for the Zustand auth store to hydrate, then attaches `Authorization: Bearer <token>` for non-`/auth` endpoints.
- Response interceptor calls `useAuthStore.getState().logout()` on `401` for protected routes — do not duplicate this logic in callers.

The home screen uses one of two endpoints depending on entitlement: `/daily-content/by-date` for everyone, and `/daily-content/full/by-date` when `isPro` — the latter is the only route that carries "The Long Read" body text, and it 403s for anyone the server does not see as PRO (the client falls back on any 4xx). Both return FREE and PRO events mixed; gate on `event.isPro`. The `dh_v7_<iso>` AsyncStorage cache key in [app/(main)/index.tsx](app/(main)/index.tsx) carries a `full_` prefix for PRO payloads, so an expiring pass cannot keep serving long reads from cache — bump the version if the shape changes.

### State

Zustand stores in [store/](store/), all persisted to AsyncStorage:
- `useAuthStore` — token + user. `logout()` does cleanup work *before* clearing: it lazy-requires `pushToServer` from [hooks/useGamificationSync.ts](hooks/useGamificationSync.ts) to flush gamification, then calls `useGamificationStore.clearUserData()`. Keep this require lazy to avoid cycles.
- `useGamificationStore` — XP, streaks, achievements, daily-goal log, calendar log, weekly recaps. Levels are generated by formula (`level * 100` XP each, 100 levels total). Keys like `categoriesRead` are stored as `Set` in memory but serialized as arrays.
- `useSavedStore` — saved events, partitioned per user id under `_perUser` with a flat `savedEvents` mirror for legacy callers.
- `useNotificationEventStore` — transient deep-link payload set by the notification handler in `_layout.tsx` and consumed once by the home screen.

### Gamification sync contract

[hooks/useGamificationSync.ts](hooks/useGamificationSync.ts) is the only place that talks to `/gamification`. It:
- `GET /gamification` on login or user switch and hydrates the local store from the DTO.
- `PUT /gamification` every 5 minutes while authenticated, on app `background`/`inactive`, and inside `logout()`.
- Sends a flat header (`totalXP`, streaks, etc.) plus an opaque `gamificationData` JSON blob the backend just stores. When adding new gamification fields, add them to both `buildSyncPayload()` and `hydrateFromServer()` here — the backend schema does not need to change.

### Theming & i18n

- [context/ThemeContext.tsx](context/ThemeContext.tsx) provides four modes: `dark`, `light`, `system`, and a `premium` palette with extra tokens (`accent2`, `glow`, `progressFill`, `streakFire`, etc.). Components consume `useTheme()` and should fall back gracefully when premium-only tokens are missing — the type intersects `Colors.dark & Partial<Colors.premium>`. The persisted key is `theme_pref`.
- [context/LanguageContext.tsx](context/LanguageContext.tsx) ships an inline `translations` object for `en | ro | fr | de | es`. Add new strings to all five languages.

### Monetization

- **RevenueCat** ([context/RevenueCatContext.tsx](context/RevenueCatContext.tsx)) — entitlement identifier is exactly `"Daily History Pro"`. `isPro` is computed as `RC entitlement || user.is_pro` so the backend webhook is the durable fallback. The client no longer calls `PATCH /users/me/pro`; the RevenueCat webhook on the backend handles that. On identity sync, `refreshMe()` (`GET /users/me`) is called to pull the latest `is_pro` from DB. **This integration is live and taking real money — do not modify it.** The paywall UI itself (including whether the close button is shown) is configured in the RevenueCat dashboard, not in this repo; `presentPaywall(trigger)` only decides *when* it opens.
- **Paywall timing** ([store/usePaywallStore.ts](store/usePaywallStore.ts), policy v2) — the paywall is deliberately *not* in onboarding. Eight intent triggers (`pass_expiring`, `deep_dive_gate`, `save_limit`, `pro_story_blocked`, `map_layer_pro`, `streak_at_risk`, `rewarded_milestone`, `third_session`), each firing at most twice, behind a 48h cooldown and a hard ceiling of 5 views per 30 days. `usePaywallTrigger` gates on RevenueCat's `ready` flag — firing before entitlements resolve would show a paywall to a paying subscriber. Note `presentPaywall(trigger)` passes the trigger to analytics only; `RevenueCatUI.presentPaywall()` is called with no arguments, so trigger strings need no dashboard configuration.
- **Ads policy** — every ad is user-initiated, and **a rewarded clip never unlocks PRO content or grants PRO time**. Ads buy breadth (tomorrow's days, five of the map layers, streak restore, the wheel's bonus round); the subscription buys depth (The Long Read, PRO stories, the four crown-jewel layers). There are no interstitials anywhere. Banner shows on `discover`/`timeline`/`saved` but **not** `today`, which hosts the Long Read teaser; AdCard only in the deep archive (`dayOff <= -7`).
- **AdMob** ([config/ads.ts](config/ads.ts)) — `USE_TEST_IDS` is `false`: **real ad units are live**. AdMob is initialized via `useAdsInit` in `_layout.tsx`. Keep the single-instance `services/rewardedAdManager.ts`; per-component `RewardedAd.load()` is what drew a fill throttle in Aug 2026.
- **Coins are retired** ([config/coins.ts](config/coins.ts), `COINS_ENABLED = false`). The store and its persisted data stay, because `unlockedEvents` rides inside the gamification sync blob and coin-bought stories must remain readable forever. `CoinIcon` renders `null`. Nothing grants, spends or displays coins.
- **Daily wheel** ([config/wheel.ts](config/wheel.ts)) — one free spin a day, plus a bonus round behind a rewarded clip. The prize table is the single source of truth: it drives both the draw and the odds screen, so the published numbers can never drift. Every segment is winnable — a 0% prize cannot be disclosed honestly, and both stores require odds disclosure for this mechanic. The **free** wheel is the only one that can award PRO time (capped at 24h, 1.8% across all PRO segments); the ad wheel awards ad-tier rewards only.

### Parallel Universes

The branching what-if game, and the app's second headline feature after the daily events.

- The tree is **pre-generated by the pipeline** (`engine/parallel.py`) and arrives as one opaque JSON string per event, `event.parallelUniverse`, keyed by language. The Java backend stores and forwards it untouched — **adding a field to the game needs no server change**, only the pipeline and the client.
- Shape: 3 decisions, 3 choices at the first two levels and 2 at the last — 13 decision nodes and **18 endings**, 31 nodes. Never hardcode those counts in UI copy; read them off the parsed tree (see `ParallelPromoStrip`/`ParallelEntryCard`, which take `{n}` placeholders) — the shape has changed twice already.
- A turn has three beats: choose → **the room answers** → time moves. Every choice carries `reactions`: two or three named voices from that exact week, each with a `mood` from a closed ten-word vocabulary. `MOOD_META` in [components/ParallelUniverse.tsx](components/ParallelUniverse.tsx) mirrors `VALID_MOODS` in the pipeline — **the two lists must stay identical**, because a mood outside the set has no colour, no icon and no valence, and the generator drops it on the floor rather than shipping it. Endings carry `legacy` voices instead: the same idea, generations later.
- Public mood is a fifth meter made of those valences. It can fall while every other bar rises, which is the point — a decision can be correct and still be hated.
- **All of the game's drawing is Skia** ([components/ParallelCanvas.tsx](components/ParallelCanvas.tsx)): the backdrop, the meters, the mood tide, the branch map, the ending radar, the rarity aura, the trajectory. `ParallelUniverse.tsx` keeps state, copy and typography — RN `<Text>` sits **on top of** the canvases, never inside them, because Skia text needs a bundled typeface and drops font scaling, screen readers and the five languages. The two layers meet only at Reanimated shared values, so the canvases keep animating on the UI thread while JS parses a 160KB tree. **Skia is a native module: changes to this screen cannot ship over EAS Update — they need a new build.**
- Entry points: the `universes` tab ([components/UniversesHub.tsx](components/UniversesHub.tsx), the whole 60-day archive of playable forks), the home-screen `ParallelPromoStrip`, and `ParallelEntryCard` at the foot of a story. All three render **nothing at all** when the event has no game — most events legitimately have none.
- Run limits live in [store/useParallelStore.ts](store/useParallelStore.ts), partitioned per user: one run a day free, unlimited for PRO. The wall is always the number of attempts, never the content. The collection of endings is the retention mechanic.
- The client tolerates old payloads: a tree generated before reactions existed still plays, and the voices panel says so rather than breaking.

### Native

- Android: `com.rexinus.dailyhistorymobile` (note: lowercase). iOS bundle id: `com.rexinus.DailyHistoryMobile` (mixed case). The repo also contains a top-level [widget/](widget/) folder with Kotlin sources for an Android home-screen widget; the previous in-app-package widget under `android/app/src/main/java/com/rexinus/DailyHistoryMobile/widget/` has been deleted (see `git status`). When restoring or modifying the widget, place sources under the Android source set, not at the repo root.
